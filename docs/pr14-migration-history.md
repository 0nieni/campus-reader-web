# PR14 迁移历史兼容

PR14 预览已应用 `20261019000100_ai_conversations`。正式数据库没有该版本，已依次应用到 `20261021000200_aliyun_reminders`。同一目录无法同时满足预览的“已应用版本不得移除”和正式库的“新版本不得倒序”两项检查。

`netlify.toml` 使用平台的分支配置覆盖，保留两条真实历史：

- 默认 `netlify/database/migrations`：原 main 七份迁移不变，追加 `20261022000100_ai_conversations.sql`。正式 main 和后续新分支使用此目录。
- 仅 `AI_module` 使用 `netlify/database/pr14-migrations`：保留预览已应用的 `20261019000100_ai_conversations.sql` 及其余原文件。已有迁移的名字和内容均不改写。

两个 AI 迁移的 SQL 内容完全相同；每个目标库只会看到符合自身历史的版本。两条历史都由正常 Netlify 部署应用，不修改托管迁移登记、不重置数据库。`AI_module` 覆盖用于兼容现有 PR14 预览，不应用于新建的普通工作分支。

本地回归先重现正式历史的倒序失败，再分别从原正式七份迁移、原预览四份基础迁移加 AI 迁移继续升级，核对已有合成账号记录保留、AI 对话可写，以及两条历史得到相同的表、索引和约束。另用 Netlify 配置解析器离线核对 main、AI_module 和新分支的目录选择。线上是否完成以实际预览和正式部署状态为准。

后续数据库变更追加到默认目录，版本大于现有最大值。已应用文件保持不可变；若继续维护旧 PR14 预览，需要同时维护其兼容目录并通过迁移历史回归。

2026-10-25：个人服务商功能向两目录追加相同的 `20261024000300_ai_provider_profiles.sql`，新增账号选择与加密配置两表；不改写前八份正式迁移或旧预览已应用的文件。升级回归继续核对两条历史最终表、索引和约束完全一致。
