# 公共竞赛来源与统一来源中心

用户确认：竞赛来源作为所有账号可见的公共目录；来源中心统一展示，沿用公告七类标签和关键词筛选，增加全部/已勾选/未勾选；学校默认勾选，其他默认不勾选；只接入实际验证可自动采集的栏目，不收录失败或仅导航的项目。

输入导航有 214 个项目、203 条链接，合并同址后 196 个地址。开发验证使用官方 lexmount-webfetch CLI 和网站实际列表/正文解析器；原始网页及本地报告只放忽略目录 .netlify-staging/competition-verification，不向生产导入测试数据。首轮 3 个栏目通过，8 个列表可读但正文容器未匹配，继续核验。未通过的入口不加入公共目录。

后续核验：数媒竞赛正文容器已按真实 DOM 适配为 .content-wrap，并重新调用 Lexmount 验证列表 2 条及样本正文 2497 字符。最终接入 4 个栏目、覆盖 5 项竞赛；其余候选未达本轮“持续列表 + 样本正文”标准，不加入。原导航的无法访问、无公告及仅单篇/PDF 等说明仅作为线索，不冒充实时测试状态。报告在 results.json，程序不读取或复制技能凭据。

实现：公共目录与现有本校、个人来源共用勾选显示设置，服务端在分页前限制为已勾选来源，精确来源筛选也不能绕过；显示选择与 AI/收藏/详情授权分离。采用显式布尔选择保存新设置，沿用既有隐藏偏好；旧版只保存隐藏列表，未记录的非学校来源按新默认关闭。公共来源只接收服务器常量中的已验证编号，沿用 Lexmount、公网/robots/域名校验、请求预算、资料库与 365 天期限；不更改提醒及 AI 搜索。

页面复用当前蓝白配色、现有字体和筛选控件；统一列表展示类型、分类、勾选、可读状态和原站入口，个人来源编辑仍保留。当前阅读学校继续作为学校权限范围，不新增跨校公告聚合。验证需覆盖账号/学校隔离、未勾选不可进入公告分页、并发保存、公共采集去重/冷却、真实本地 SQL、桌面/手机浏览器及完整构建。完成后再合并部署并分别报告代码发布与真实凭据联调。

最终验收：526 项测试（189 web / 337 cloud）、npm ci/typecheck、普通构建及 11 函数完整构建通过；真实 SQL 与 Playwright 桌面/手机验证通过，采集定义与真实报告逐项吻合。PR #20 已合入 main 的 fb82e30，正式部署 6ade2546773f7ef622ceab31 为 production / ready，网页 200，未登录 API 401 / no-store。凭据配置与真实账号采集仍待所有者安全配置后验证。完整交付记录见 PROGRESS.md。
