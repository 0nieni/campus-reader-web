## 注册行为

用户已选择“邮箱注册并验证后自动开通”。继续使用现有 Netlify Identity，不新建密码库、不写密码到业务数据库。每账号依可信 Identity UID 独立保存资料，原所有者的工作区命名不变。

注册入口调用本站 `POST /.netlify/functions/auth?op=signup`，校验同源、JSON大小、邮箱、密码长度与字段白名单；不接受 owner、角色、权限或回跳地址。密码12至256位，提交后前端立即清空密码与确认框，不存 Storage，也不自动重试注册。服务端调用官方 SDK `getSettings()` 和 `signup()`，先确认已开放注册且自动确认关闭。错误只返回本站固定说明，不回显原始认证响应、密码或令牌。

注册成功仅显示“下一步，确认你的邮箱”，不会直接读取工作区。确认邮件回到网站后，确认令牌从URL片段取入内存并立即移除；验证期间不读取公告。官方 SDK `confirmEmail()` 完成后，重新从本站认证端点核验会话，再打开本人工作区。失效链接提供返回登录入口；可联系管理员重新发送确认邮件。原邀请接受流程仍保留。

## 正式站点启用步骤

代码已实现，实际注册必须在 Netlify 部署并设置 Identity 后才能使用，本地合成预览不会发邮件。

1. 部署本分支对应代码。样式和注册本身没有新迁移；因为分支包含上一轮模型配置功能，首次部署该功能时仍需它的迁移和 `AI_PROVIDER_ENCRYPTION_KEY`，见 [模型接入说明](ai-provider-profiles.md)。
2. Netlify 项目进入 **Identity → Registration → Registration preferences → Configure**，将 **Invite only** 改为 **Open**。
3. 进入 **Identity → Emails → Confirmation template → Configure**，不要勾选允许用户跳过邮箱验证的选项，保存。若开启自动确认，本站注册端点会拒绝继续注册。
4. 使用真实收件邮箱验证：注册只显示待验证；未验证密码登录失败；点击确认邮件链接后打开独立工作区。原有成员仍能登录，其他账号无法读取原账号数据。

Identity 邮件使用平台现有发件方式，不使用本站的提醒发信密钥，也不要求自定义邮件模板。确认邮件回跳域名应为本站配置的 HTTPS 地址。

官方依据：[注册与登录](https://docs.netlify.com/manage/security/secure-access-to-sites/identity/registration-login/)；SDK API 以本项目锁定的 `@netlify/identity` 2.0.0 源码和 README 校验。线上设置需要管理员在项目控制台完成；本轮没有改动生产配置或发送真实邮件。
