# 手机桌面应用通知与提醒内容

用户反馈手机桌面应用未显示公告提醒，截图中的 Chrome 通知正文为“点按即可复制该应用的网址”，页面同时出现“请先开启此浏览器推送；测试每分钟最多一次”。这条 Chrome 提示不能作为本站公告提醒已送达的证据。截图中的网站报错也不能区分订阅不存在与重复测试。

## 修改后的行为

- 测试通知明确显示“校园阅览室｜测试通知”。接口分别返回 `PUSH_RATE_LIMIT` 和 `PUSH_NOT_READY`；60秒内重复测试显示冷却，不再提示重新开启推送。厂商返回404/410时按设备绑定版本移除失效端点。
- 提醒中心显示当前浏览器或桌面应用的绑定状态，恢复前台时重新核对。账号已开启的浏览器总数不能替代当前入口的状态。失效时显示开启入口供本人修复。
- 同一推送公钥下已有订阅直接重新绑定，不销毁可能被 Chrome 与安装应用共用的端点；修复绑定失败时保留原订阅。公钥确实变更时仍重新订阅。
- 正式事项通知以公告标题为标题，正文包含事项名称及本人设置的到期时间，统一标注北京时间。提前7/3/1天发送时仍显示事项真实到期时间，而不是提前发送时刻。已开启的事项邮件同步显示相同信息，验证邮件、测试邮件及既有开关保持独立。
- Worker 读取服务端加密载荷；空消息和格式异常保留通用提示。不同事项使用不同通知标签，避免全部覆盖为同一条。通知点击仍只进入本站提醒中心；载荷不能指定外部跳转或图标。
- 旧应用重新打开时检查 Worker 更新，新 Worker 可接管当前页面；不缓存网页、账号令牌或公告正文。通知内容可以在锁屏显示，是否显示由手机设置决定。

不增加依赖、数据库迁移、定时器或模型调用；不轮换已有 VAPID、FC 或邮件密钥。用户未选择的邮件通道不会开启。

## 验证与边界

- 修改前，新 Worker 载荷回归复现“实际显示校园阅览室，未显示公告标题”的失败。
- 完整633项回归通过：前端245项，后端388项。覆盖实际到期时间、提前提醒、消息载荷、订阅共享与失败恢复、限频、前台复核、取消改期、权限撤回、邮件开关和发送去重。
- `npm ci`、类型/指南检查、普通构建和11函数 Netlify 完整构建通过。
- 本地真实 Vue 组件在390×844、360×640和1366×900检查无横向溢出，绑定刷新与冷却按钮可用。真实浏览器 Worker 的 `getNotifications()` 返回两条不同标签的通知，包含合成公告标题和北京时间到期时间；组件未出现 JavaScript 运行错误。
- 本地验证使用合成账号、SQL与发送桩，浏览器注入合成 PushEvent。它不代表真实 FCM 传输或小米锁屏送达已经通过。没有读取生产账号的提醒资料，也没有发送真实用户邮件或推送。

## 手机复测

发布后从桌面“校园阅览室”图标重新打开，进入提醒中心核对“当前桌面应用：推送已绑定”。若未绑定，点击开启并允许通知。发送测试通知后，应看到明确的测试标题；60秒内不要重复点击。再选择公告，设置几分钟后的事项，确认浏览器通道已登记，关闭页面并锁屏核对公告标题与到期时间。主动退出账号仍会解绑当前订阅。
