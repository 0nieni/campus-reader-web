# AI 搭子按需联网设计

日期：2026-11-03。状态：待用户确认；本文件是方案，不代表功能已实现。

## 目的与依据

用户要求借鉴分享对话中的 AstrBot 做法，为网站 AI 搭子提供联网能力。分享页说明的核心是 Function Calling：模型决定搜索词、选择要阅读的网页，网站执行 DeepSeek Search / Fetch，再将结果交回模型继续回答。

现有 main `ea95541dbd7dcec3d604cb592ac639f4fff8c4ce` 已接入 DeepSeek 官方搜索与正文读取，聊天仍主要依靠 `chatSearchQuery` 规则触发，搜索后固定尝试读取前三条。模型适配层目前拒绝工具调用。任务支持官方额度预占、幂等、逐步执行、取消、状态不明暂停、资料权限复核和个人服务商。

参考：用户提供的 https://chatgpt.com/s/cx_6ae9f32f7d20819187d6bb6f40adec2e 、AstrBot 提交 f926af99ec5f8bd85b64413f8bfad55da76ef73b、DeepSeek 官方 Search / Fetch 与 Tool Calls 文档。借鉴行为与接口，不复制整个 AstrBot 或执行分享页中的命令。

## 方案选择

1. 推荐：在当前逐步任务中加入工具调用。支持工具调用的模型按需搜索、选读网页并回答；沿用现有手动搜索和权限系统。较固定关键词方式更适合一般公开互联网问题，需要适配模型工具消息和任务状态。
2. 仅扩大关键词规则：改动少、调用次数少，但仍无法让模型根据搜索结果决定下一步，与参考方案的目标有差距。
3. 接入完整 AstrBot 服务：需新增部署、状态和权限桥接，现有网站已有搜索服务和任务执行器，因此本次不采用。

用户尚未回答的体验选择：默认由 AI 自动决定，或增加用户允许联网的开关。本方案暂按第一种作为建议，不能把未回答当作批准。

## 目标行为

- 用户直接提问，模型可以直接回答，也可以请求 `web_search_deepseek` 或 `deepseek_fetch_web_page`；开启能力不等于每条消息都搜索。
- 搜索只给模型候选标题、公开链接及读取状态；正文必须经过网站核验并实际读取，才成为回答证据。模型自行选读候选网页，摘要不冒充正文。
- 回答保留现有 R 编号与可点击原文，轮次显示实际搜索状态、候选/可读正文数和当前处理阶段。
- 搜索与聊天模型独立：继续统一使用后台官方 DeepSeek Key，个人 API Key 仅送往用户选定的聊天服务商。模型切换只影响新轮次。
- 用户明确不要联网时，服务端不提供也不执行搜索工具；现有侧栏手动搜索继续工作。
- 不支持工具调用的模型明确保留现有搜索流程，不能偷偷更换模型或伪装自动联网成功。
- 没有选中公告时仍可进入工具决策；取得有效正文后生成有来源的回答。未取得正文时直接说明缺口，不能被旧的“必须先选公告”逻辑拦住，也不能编造引用。

## 实现边界

实现继续使用 Vue 3、TypeScript、Netlify Functions 和现有数据库 JSON 任务记录。独立分支 `codex/assistant-auto-web-tools`，基于最新 main；不覆盖旧工作目录。不新增服务商、依赖、数据库迁移、定时器或提醒发送能力。

模型协议接线分别处理 OpenAI Chat 的 tool_calls、Responses 的 function_call、Anthropic 的 tool_use、Gemini 的 functionCall；严格校验工具名、参数、调用编号和完整结束状态。普通阅读、连接测试和旧任务仍使用原文本适配器，不接受意外工具调用。工具能力不等于所有用户自定义模型都已通过真实兼容测试。

同步修改 `docs/ai-reading-guide.md` 中“不能自行发起搜索”的旧约束，改为仅可请求程序实际提供的工具，并运行指南生成器；未提供工具的旧任务不能据此声称能够执行搜索。

## 任务、预算与失败

- 一次 `ai.chat.step` 最多执行一次模型请求或一个工具请求，将下一步安全保存后返回；前端沿用已有逐步执行。不能在单个 HTTP 请求内无限循环。
- 每轮建议最多 2 次 Search、3 次 Fetch、4 次模型请求；最多使用 8 篇资料，单次搜索返回最多 5 条候选。达到限制后停止工具扩展，让模型基于已核实资料回答并说明缺口。
- Search 继续执行每账号每天 20 次、至少间隔 15 秒的原有限额；工具请求不豁免限频，不后台等待或自动重试。
- 一轮成功回答只结算一次官方个人额度；每次实际模型请求分别纳入平台调用/估算 token 预算。个人 API 不扣官方次数。模型和 Search / Fetch 的供应商计费仍分别发生。
- 准备和执行都先取得原有幂等锁；重复请求只返回已有状态，不重复执行工具。正在请求时取消，拒绝接受后续输出；状态不明暂停且不自动重发，沿用核查结算入口。
- 搜索失败、无结果、正文无法读取、限额用尽等成为真实工具结果；界面不得显示成功搜索或虚构读过的来源。用户明确要求实搜而搜索失败时保留清楚的失败说明。

## 数据与资料权限

- 搜索词只允许与当前用户问题有关的公开主题，不把自动记忆、历史问答、私人资料正文、邮箱或凭据发给搜索接口。公开学校名称来自服务端已授权选校记录。
- Fetch 只允许本轮搜索给出的已核验公开 HTTPS 候选。不能凭模型任意 URL 请求内网、登录页、凭据链接或未知私有地址。
- 沿用公网 DNS、robots、跳转与已有 URL 来源策略检查；已有被撤回或禁止 AI 的链接不得通过重新搜索导入绕过。
- 模型请求前与结果接受前复核本轮及历史资料的账号、学校、版本、有效期和来源许可；工具新增正文同样纳入这一校验。
- 工具消息是不可信资料，不能改变系统规则、工具权限、预算或官方配置。工具 transcript 不含密钥，随对话固定 24 小时到期清理；页面不展示原始供应商错误体。
- 正文只返回有界摘录并明确标示截断；统一限制模型上下文大小，不能为继续联网而无限拼接网页。
