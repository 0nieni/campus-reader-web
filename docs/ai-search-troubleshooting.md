# AI联网搜索与排查

2026-11-01：当前搜索通道切换为 DeepSeek Search / Fetch，保留 PR35 的自然搜索、来源许可与真实状态提示。部署与真实联调结果单独记录。

## 先区分三个事实

- **代码接入**：默认搜索与正文读取为 DeepSeek Search / Fetch，旧 Tavily 适配器只保留兼容测试，不用于正式默认入口。
- **服务端已配置**：当前函数取得有效格式的后台 `AI_CHAT_API_KEY`，且 `AI_CHAT_BASE_URL` 为 `https://api.deepseek.com` 或其 `/v1`、Chat Completions 路径；不证明 Key 权限、余额或服务连通。
- **本次真实搜索成功**：只有本次供应商请求成功、响应通过验证后，search.state才为complete。候选不等于取得正文，也不证明资格、日期或全校覆盖。

全部账号复用网站后台官方 DeepSeek Key 搜索，个人保存或临时填写的聊天模型不改变搜索凭据。中转/OpenAI 地址不允许复用到 DeepSeek 搜索，以免误发其他服务商的密钥。无需新增服务商账号或环境变量；Search / Fetch 按请求单独计量，见 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/search/)。

## 怎样使用与判断

可直接问“帮我查一下最近学校的比赛”“最近我们学校有什么比赛可以报名”“帮我看看学校有没有新的讲座”。也可点右侧“联网找资料”。“你能联网吗”只检查网站当前配置，不实际搜索，不调用模型、不扣官方次数。

搜索沿用主线的全网公开资料能力。自然校园发现问题保留当前学校语义，仅外发固定主题词和服务端学校名；明确说“联网搜索 TypeScript 教程”等则保留本次公开查询主题，最长200字符，不强加学校域名。不发送对话历史、自动记忆、用户偏好或私人联系方式，含敏感信息的显式主题退回安全主题词。外部网页按真实网站标注，不当作本校官方公告。固定校园词包括比赛、实习及蓝桥杯、挑战杯、数学建模等部分名称，隐式自然发现仍采用保守匹配。“不要联网”“只查看已有公告”、引用指令、假设和他人说法不会触发搜索；普通截止时间/材料追问继续使用授权公告。

状态和实际候选/正文计数显示在回答前面；旧接口没有计数时不补零。candidateCount是候选经过公开URL与来源许可核验后的数量，readableCount是其中取得正文且当前许可允许AI处理的数量，均在合并已有推荐之前计算，不拿本地公告凑搜索命中数。所选资料占满八篇时给出容量提示；部分候选复读失效时重新核算，不把容量截断伪报成没有正文。

| 本次结果 | 当前行为 |
| --- | --- |
| 未配置、授权失败、限流、额度不足、超时等 | 直接解释真实原因，不再自动调用模型用旧公告回答；已有公告入口保留 |
| 搜索成功，零候选 | 明确本次未找到符合范围的线索，不把已有公告称为新结果 |
| 找到候选但无可用于AI的正文 | 只展示真实状态与核验过的原文入口，不把搜索摘要当正文，不调用模型 |
| 有可读且允许AI的正文 | 沿用引用、来源授权和额度流程生成解释；已收录链接仍保留原来源策略 |

程序说明显示“未调用模型”。搜索、候选读取仍可能产生第三方资源消耗；每账号每天最多20次、至少间隔15秒。只有成功的模型回复计官方三轮；搜索失败/空结果不会消耗一轮模型额度。相同请求重试只查同一轮状态，不自动重搜。

## 网站管理员检查

1. 先核对网站实际发布的提交是否包含本次修复。推送分支、构建通过、正式站更新是不同状态。
2. 确认 Netlify Production 的 Functions 能读取有效 `AI_CHAT_API_KEY`，`AI_CHAT_BASE_URL` 为 DeepSeek 官方地址，保存后重新部署。不要写进 VITE_ 变量、前端、仓库、日志或聊天。Netlify CLI 对标记为 secret 的值可能只返回隐藏占位；用占位请求得到的 401 不能证明线上真实 Key 失效，不能据此覆盖生产密钥。
3. 页面配置说明或可信登录的ai.status.searchConfigured能确认函数是否读到非空配置；旧部署缺少字段时视为未知，不能推断已配置。
4. 实际搜索一次，按返回code排查；不能凭模型说“我查过了”判定成功。

| code | 含义及处理 |
| --- | --- |
| unconfigured | 函数未取得非空搜索配置，检查服务端部署配置 |
| authorization | 供应商401/403，管理员核对搜索凭据与账户授权 |
| quota | DeepSeek 402，管理员检查账户余额 |
| rate_limited | 供应商429或本项目搜索间隔/日次数限制；按提示稍后再试 |
| timeout / network | 搜索超时或连接失败；核对服务连通性，不直接归因校园网络 |
| provider / invalid_response | 供应商异常或响应不符合协议；不能当作没有新公告 |
| invalid_scope | 学校域名限定适配器无法形成许可域名时检查学校配置；默认全网模式不以学校域名为前提 |

所有错误只输出分类及固定说明，不返回上游原始正文、异常或凭据。成功但正文读取受登录、来源许可等限制时，仍不能绕过授权。

搜索导入与程序回复原文入口共用有界同URL策略核验，使用一致的网址规范化，并检查已经撤回或来源移出的旧记录；撤回记录不能通过新临时ID恢复。URL策略核验在只读一致快照中每页读取200条安全元数据，不读取其他账号或私人正文；每次URL核验最多10000条，扫描及SQL执行预算5秒（连接池等候不能由此取消）；五个候选及重定向可能各自重新核验，超预算或仓储不支持可靠查询时保守拒绝新增临时正文和不确定的临时链接。它替代早期200条feed查重限制；普通推荐仍使用原有200条候选池。预算降级不能被说成没有搜索结果；已有经授权的公告仍可阅读。CloudBase兼容仓储没有该策略接口时采用同样保守降级。

## 为什么它不像成熟聊天产品

目前主要路径仍是“选取公告→分批提取→生成有引用的解释”，近期历史预算3500字符，另有1200字符较早摘录。API使用的模型、提示、材料与产品交互都可能不同。本轮已确认并修复自然表达漏触发，以及搜索失败后旧资料回答造成的误解；能力问题也不再依赖公告或强制引用。

一般聊天、情绪表达和纯澄清仍未成为独立对话路径；现有模型答案强制引用也可能影响自然澄清。这些是后续改进点，不能把本轮搜索修复称为完整的聊天体验重做。

## 验证边界

开发回归通过真实程序链路、合成公告及模拟 DeepSeek 响应验证触发、隐私、固定端点、幂等、错误分类、robots、公网 DNS 和正文证据。正文读取前先以无凭据 HEAD、固定公网 DNS、同域与 robots 规则核验重定向，再调用 Fetch；最终地址重新经过已有链接许可核验。无法核实的跳转不读取正文。Fetch 不返回它内部的最终 URL，因此不能宣称独立核实了供应商内部跳转。整轮新网页读取采用 24 秒预算，避免同域排队继续发起过时请求。真实效果应通过部署后的已登录站内入口验证；配置检查、代码发布和供应商验收分别记录。最新提交和测试证据见 [PROGRESS](../PROGRESS.md)。
