# 对话语言评测

本地自动化测试验证资料流、模型指令、权限与额度；不能证明回答自然。本评测用八类合成情境观察真实模型的语言效果，不接触站点用户数据，不执行真实搜索，也不写入生产数据库。

## 运行

先安装开发依赖。在项目根目录执行：

```sh
node --import tsx tools/evaluate-ai-chat.ts --dry-run
```

默认也是 dry-run：完整走对话/任务流程，使用固定模拟回复，零服务商请求；输出不能用于评价语言效果。

真实模型由服务端环境变量 `AI_CHAT_BASE_URL`、`AI_CHAT_MODEL`、`AI_CHAT_API_KEY` 配置，不要把值写进命令、文件或评测记录。配置后可先执行单个场景：

```sh
node --import tsx tools/evaluate-ai-chat.ts --live --case=continuity
```

去掉 `--case` 执行全部八类。live 会产生真实模型费用，每轮可能包括资料批次和最终回答，整个运行最多 60 次模型调用；失败、状态不明或未通过引用检查即停止，不自动重试。调用状态不明时先检查服务商记录，不盲目重跑。该开发命令使用独立内存测试账本，不消耗或重置真实账号的官方日额度；平台共享预算也不会因此记账，测试人员应单独控制调用费用。

每次结果保存到被 Git 忽略的 `output/ai-evaluation/`。记录模式、调用次数、问答、引用、处理状态和人工评分空位。`--live` 只代表请求了真实模型，`languageReview: pending` 仍需人工审阅后裁定。未配置时直接拒绝，不降级成假 live。资料域名 `.invalid` 为合成标记，不是实际学校来源。

## 逐项评审

用例在 [chat-cases.ts](../apps/cloud/evals/chat-cases.ts)，覆盖推荐、连续指代、简单追问、资料不足、歧义澄清、用户纠正、阶段完成和拒绝建议。

每项以 0（不满足）、1（部分满足）、2（满足）评价，并保留具体失败的问答：

| 检查项 | 判断依据 |
| --- | --- |
| 直接回答 | 先解决本轮问题，少重复背景 |
| 有证据 | 日期、资格、材料等事实由本轮资料支持；引用号不混用 |
| 连续性 | “第二个建议”对应上一轮真实回答；纠正后更新理解 |
| 建议质量 | 有用户目标或公告依据，具体、适量，能说明帮助 |
| 停止延伸 | 简单查询、资料不足及拒绝建议时停止扩展 |
| 能力诚实 | 不假装记得未提供的信息，不承诺后台跟进或提醒 |

编造日期、资格、来源，忽略用户拒绝，或承诺未实现的后台动作，应单列阻断问题，不能用其他项高分抵消。对话最终结果仍经过生产引用校验；如果模型只做澄清而未给引用，现有校验可能拒绝，应记录为实际评测发现，不能改评测结果冒充通过。
