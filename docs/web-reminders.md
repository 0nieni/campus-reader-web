## 以下为旧 QStash 版本记录

本版实现站内提醒、ICS日历导出及QStash延时任务驱动的标准Web Push，按本人逐篇设置的时间发起后台发送。“学校与关键词”已移除。当前PR仍待审核，真实队列需配置后正式发布；预览不发送真实推送。见 [配置指引](qstash-setup.md) 和 [方案评估](minute-reminders-evaluation.md)。邮件提醒和自动AI日期提取不在本版范围内。

## 使用方式

- 公告列表“用 AI 生成摘要”左侧点击“加入提醒”；公告详情也保留加入入口。先加入提醒中心，不自动填时间，不要求收藏，也不调用模型或扣 AI 次数。
- 提醒中心右侧“选择公告”支持关键词搜索、标签筛选和分页，勾选后加入；一次最多20篇，已经加入的公告标记并禁止重复勾选。复用当前学校、本人标签和授权范围。手机上选择栏可展开／收起。
- “时间提醒”中每篇公告分别设置事项名称、北京时间和提前7天、3天、1天、到时档位；不提供批量统一时间。未设置时间时显示“待设置时间”，不触发通知，也不进入日历。已经过去的提前档位不再创建；全部已过去会要求重新选择。
- 左侧“提醒”只保留“消息通知”和“时间提醒”。支持编辑、移出、标为已读、打开原公告及导出单条／全部未来提醒。显示待设置及可导出数量；没有未来事项时禁用导出并给出设置指引，已到时间的旧提醒可以重新设时。
- 时间保存后请核对后台状态：待配置、未开启设备、待登记、已登记、远期待登记、登记失败、厂商已接收、失败或结果未知。无设备或未配置时，不声称系统提醒已生效。三类设备开启方式在“说明与设备设置”内，支持安装图标。
- 网页可见时最多每5分钟检查一次，恢复前台至少间隔1分钟；接近本人已设提醒时缩短下一次检查等待。标签和通知保存在本人账号，不写浏览器 Storage，不在 Service Worker 中缓存网页、账号令牌或公告正文。
- QStash按指定UTC时间回调本站，不需要网页打开；设备显示时间仍取决于网络及系统。多档过期时只处理最近档位；迟到超过24小时的任务不再发送，站内仍显示历史通知。
- ICS 使用 UTC 时间及 VALARM。实际系统提醒取决于导入的日历和系统设置；网页编辑／取消不会自动更新已导入的日历，需要在日历中同步修改。文件由用户保管。

## 浏览器推送

用户在“提醒中心”主动开启并授予通知权限后，浏览器注册不含缓存逻辑的推送 Worker。每账号最多5个浏览器，端点全局唯一绑定一个账号。退出登录时注销当前浏览器订阅；关闭推送不删除站内通知。

iPhone／iPad 需使用支持 Web Push 的系统并把网站添加到主屏幕，再从主屏幕打开。内嵌浏览器、网络限制、系统通知权限或省电设置可能影响推送；界面检测能力并保留站内／日历入口。[Apple Web Push 说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

推送只包含“你有新的提醒，请登录提醒中心查看”，不含学校、公告标题、私人来源或用户标识。QStash消息仅带随机任务编号。点击通知打开登录后的提醒中心。服务端先保存站内通知，再按设备绑定独立认领和加密发送；阅读站内消息不会吞掉尚未发送的系统推送。厂商接收不等于设备显示。

推送尝试先持久化认领，重复回调不重发；未知或失败的设备发送不盲目重试。404／410端点按绑定版本删除，不能误删已转移账号或重新订阅的设备。新设备不补发此前消息。改期／移出事项使旧任务失效，已交给系统的通知可能仍显示。测试通知每设备每分钟一次，只发给当前账号绑定的端点。

## 数据、额度与部署

- 每账号最多100条提醒（含待设时间）、5个浏览器。站内通知显示最近90天、最多200条。旧关注存量不删除，但分钟模式不执行关注扫描、不接受关注新增／修改。
- 第五份迁移 `20261020000100_web_reminders.sql` 保存原提醒；新增第六份 `20261021000100_minute_reminders.sql`，增加事务outbox、设备发送回执、登记额度和设备绑定版本。原五份迁移均不改，不回填历史通知。
- 读取、导出及到点发送前重验公告状态、保留期和当前来源权限；个人标签不扩大权限。回调由官方SDK验证签名、原始请求体、目标URL和有效期，未验签不访问任务数据；只接受正式站点固定回调。
- 原每日清理增加90天任务／回执清理，已取消远期任务按取消时间清理；保留尚未到期的任务。原AI到期清理优先级不变。
- QStash免费延时最长7天，登记采用未来6天窗口。保存、读取及新设备订阅补登记；每天北京时间09:00／20:00做滚动登记修复，不每分钟轮询SQL。维护按独立游标公平轮换最多100个已订阅账号、每轮最多80次发布，18秒软预算；每次网络3.5秒截止。大规模用户需重新评估容量。
- 按计划发送日期保守限制最多400次发布预约，QStash每条最多1次回调重试。取消和不确定发布不退预约计数；不保证覆盖外部账号的全部计费用量，也不自动升级套餐。队列登记失败在界面可见，任务保留以便恢复。
- `WEB_PUSH_PUBLIC_KEY`／`WEB_PUSH_PRIVATE_KEY` 与QStash三份密钥及API地址仅生产Functions使用，不进入VITE变量、源码、客户端或日志。预览禁用真实队列及推送；配置清单见qstash-setup.md。
- 没有付费升级、邮件服务、用户邀请、真实模型调用或生产用户资料读取。保留官方 AI 每账号每天3次和 BYOK。
