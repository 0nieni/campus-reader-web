# 公告详情自动摘要

本功能按2026-10-30交接构图，只在原文链接和现有正文之间加入摘要。主标题、原正文、现有紫色模板、列表、收藏、AI选择、标签及提醒操作保留。摘要不自动创建提醒。用户确认沿用现有官方模型、独立平台额度，每天最多100次尝试；最新范围已改为开启后自动补齐系统内所有符合条件的公共公告，包含所有学校、公共来源和历史公告，不再限定新采集正文。

开发验收使用已安装的 Lexmount Web Fetch CLI 读取两篇指定公开公告，并核验渲染DOM。CLI和个人凭据不打包到服务器；正式采集复用已有 `lexmount-pages.ts` 的官方WebFetch API适配、URL/最终地址/来源许可校验，以及经正文容器提取的文本。WebFetch标题不覆盖公告标题，导航污染不直接交给模型。摘要只使用网页正文，不读取或引用已有附件提取内容，原附件阅读功能保持。

正文成功保存后登记独立任务；任务以部署数据范围、公告、学校、许可签名、正文和解析/提示词/Schema版本去重。后台一次只处理一个模型请求；详情及状态查询只读取缓存。字段和每个时间节点都带可定位原句，拒绝缺证据、凭空数字/邮箱/URL、HTML、日期冲突、虚构时刻和结构错误；模型输出不含标题及动态阶段状态。私有资料、邮件、AI搜索临时资料、停用来源和禁止AI的来源不入队。发送前与写回前重查版本/权限，旧结果失效不混入新正文。

## 服务端设置

- `NOTICE_BRIEF_ENABLED=true`：启用新任务，默认关闭。关闭不删除原文和既有有效只读摘要。
- `NOTICE_BRIEF_DAILY_CALLS=100`：北京时间每天的站点总尝试上限；失败同样计入，不保证每天恰好生成100篇。
- `NOTICE_BRIEF_DAILY_TOKENS=1000000`：独立token保护上限，输入UTF-8字节数加1500输出token和固定余量预占。成功按有效usage结算；缺失/无效usage和未知结果保守按预占结算。个人每日三次AI阅读及原平台账本不改。
- 沿用 `AI_CHAT_BASE_URL`、`AI_CHAT_MODEL`、`AI_CHAT_API_KEY`，仅服务端读取；输入上限12000字符、输出1500token，过长不静默截断。
- 沿用 `MATERIALS_JOB_SECRET` 和固定配置的 `URL` 签名调度独立 `notice-brief-background`，不新增定时器，不依赖请求结束后的普通Promise。新任务唤醒后台，既有日常采集结束补一次唤醒；预算不足延至次日，结果不明停止自动重发。

模型凭证与预算必须在目标环境单独配置；当前预览运行时禁用真实模型，后续受限预览验收需另行限定样本与授权配置，不将生产密钥写入源码、前端或日志。新SQL迁移 `20261030000100_notice_briefs.sql` 同步默认、PR14和PR17历史，旧迁移不变。每日清理有界处理过期缓存及未知请求预占，失败不删除原公告。

## 历史自动补齐

沿用现有北京时间每日02:45资料采集调度，在资料后台结束时唤醒摘要后台；开启后的下一次该调度即可从空队列启动历史扫描。摘要后台也会有界续跑，无需用户逐篇打开。保留期为已有365天规则，私人、邮件、临时搜索、停用、禁止AI及不符合学校/来源许可的资料均排除。缺正文时复用有效正文档案，或经原有Lexmount及公网/来源校验采集原文；本轮只采集正文，不下载附件，不将既有附件文本发给摘要模型。

独立迁移 `20261030000200_notice_brief_backfill.sql` 在三条历史中一致追加，保存每个环境范围的持久游标和每日扫描/读取计数。一次后台最多扫描500条元数据、每天最多5000条，历史正文读取尝试每日硬封顶100次，与模型调用上限分开；即使首次验收将模型调用限制为2次，也能跳过不可用网页继续寻找可用正文。历史入队量同时受当日剩余模型尝试数限制，避免提前读取多余正文。已有同版本有效结果和未决/失败记录不重复发送；状态不明仍须先核查用量。历史与新公告共用原有100次模型尝试和token账本、200条有效队列上限及同一后台租约，不重置个人额度。预算或读取额度用完保留游标至次日；增加额度后可继续尚未完成的扫描，保留原游标和当日累计计数。完成一轮后次日复查，补入游标后方新增或后来恢复许可的公告。个别原站失败不阻塞其他公告，也不无限唤醒。数量较大时需要多日，不能保证一天全部完成。

详情及状态接口仍只读缓存，打开页面不会启动历史扫描、采集或模型调用。网页设计不变，只更新“等待后台补齐”的状态文案。

## 前端与时间

正文去重和缓存匹配采用同一规范化规则，去除零宽字符、行首尾空白和多余空行；仅格式变化复用原任务，真正新增正文仍使旧结果失效。规范化指纹不含资料库追加的附件文本。日期校验将时刻绑定到其对应日期，不能从同一句的其他日期借用时刻；同一日期的起止时刻仍可分别保留。解析及校验版本已更新，使旧规则下的缓存失效。过期pending任务不会触发后台唤醒、续跑或占用有效队列容量。

`NoticeDetail.brief` 可选，旧服务端仍可读取。`feed.brief` 为授权只读查询，复用账号/匿名身份、当前学校和公告许可。缺摘要或服务异常不阻断原正文。

摘要采用现有紫色、小圆角和同宽容器；桌面标签/值两列，手机单列，长邮箱/URL换行，无内部滚动。首次显示核心字段，长要求可展开，原文依据使用原生details。pending仅在页面可见时有限查询，最多20次且不超过90秒；关闭或切换公告即停止。日期状态使用服务器时间偏差每30秒更新；日期精度保持为日期，当日截止不伪造时刻。报名、审核和带条件补交各自计算状态。
