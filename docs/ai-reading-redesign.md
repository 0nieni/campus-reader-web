## 1. 原始文档阶段范围与基线（历史）

本轮只新增本方案、[对话式阅读规范](ai-reading-guide.md)，更新 [README](../README.md) 并维护 [进度记录](../PROGRESS.md)。不删除旧模块、不改业务代码、不迁移数据库、不提交或推送。

当前 Vue 3 + TypeScript 前端通过 Netlify Functions、Identity 和 Database 访问数据。已有学校目录、按账号保存的选校记录、学校公开来源、自定义网页/RSS/JSON 来源、收藏、个人标签及模型调用流程。

当前 AI 阅读仍是“勾选 1～8 篇公告 → 预览资料 → 选择摘要、提纲或问答 → 生成报告”。`apps/cloud/src/reading-guide.ts` 保存 v1 指令，`ai-service.ts` 在最终汇总时要求七节报告；中间批次另用 `reading-batch-guide.ts`。没有多轮对话、行为推荐或搜索引擎发现新来源。新增 MD 不会自动改变上述实现。

当前官方额度按任务计次，默认每天三次、北京时间零点重置；BYOK 不扣官方次数。任务正文创建满 24 小时拒读，访问时清理并由每日任务兜底，不承诺准点物理删除。计划中的“三轮回复”需要后续代码适配，不是现有计费行为。

## 2. 目标体验与建议

### 2.1 首次接入与推荐

队友在首次登录后引导选择学校，学校必填，兴趣与目标可选。已有学校的老用户无需重复填写。AI_module 读取已保存学校，不自建另一套选校状态；学校缺失时给出进入选校引导的入口，不推断学校、不混合跨校内容。

进入 AI 阅读，先展示最多五张推荐公告卡片及提问入口。卡片包含标题、学校、来源、发布时间、最近读取时间、推荐理由、正文状态和原文入口。未知时间显示“未提供”，读取时间不冒充发布时间。入口包括“最近有什么适合我”“这条公告需要准备什么”。打开推荐列表不自动调用模型。

用户可以查看全部公告、修改关注点，或标记“不感兴趣”。不感兴趣先排除对应公告，不把一次反馈扩大为永久屏蔽整个类别；可撤销。

### 2.2 可解释推荐

首版复用现有标签和文本检索，不引入向量数据库、画像模型或后台模型摘要。先校验学校、账号权限、来源可用性和公告状态，再排序；个性化分数不能越过权限或 AI 使用许可。

建议首版排序采用分组优先级：明确兴趣/目标命中 → 开启行为学习后的近期兴趣命中 → 其他近期公告。同组按发布时间降序，未知发布时间置后，再用稳定公告 ID 排序。首屏若有候选，保留一个位置展示不同关注类别的近期公告。无偏好时只按近期公告推荐，并说明“按发布时间展示”。

明确兴趣使用用户选择的标签及主动填写的关键词匹配，不用模型猜测专业、年级、身份或资格。行为学习默认关闭；开启后仅统计近 30 天信号，每人每校同一公告每天点击最多贡献一次，同一类别每日最多五次。收藏作为辅助信号；关闭行为学习后不再用于推荐。行为统计只改变辅助分组，不覆盖用户明确意愿。清除行为记录同时清除其派生权重，不清除收藏本身。

推荐理由必须能对应实际命中，如“命中你填写的‘竞赛’关注点”；不得把点击写成报名意愿，或把兴趣匹配写成已经符合参与条件。首版不自动倒推不完整日期，也不根据发布时间断言报名仍有效。

### 2.3 连续追问

对话默认人格为自然干练、有温度，先直接回答，再在目标明确、准备参与、完成阶段步骤或存在明确后续要求时，补一两条低成本的具体建议，说明做什么和有什么帮助。简单查时间、要求简短、资料不足或已拒绝同类建议时停止延伸；不每轮反问、不机械夸奖、不假装知道用户经历，也不承诺后台跟进。实际规则及八类短示例见[对话式阅读规范](ai-reading-guide.md)，已生成到 v2.1 指令，真实语言效果仍待模型评测。

对话围绕本校公告展开，可从卡片发起，也可直接输入问题。用户手选公告时优先限定在该范围；否则由后端检索相关候选，再挑选有权限且允许 AI 处理的资料。每轮最多使用八篇资料，沿用现有六万字符输入上限，超限先缩小资料范围，不能静默截掉关键条件。

回答先回应问题，必要时列公告卡片、来源和建议，不再固定输出七节报告。“它”“这个报名”等指代不清时先澄清；对话历史只能帮助理解问题，不能作为新的事实来源。

用户可新建对话、清除对话或导出本人结果。切学校时开启新会话并清空当前资料；退出、换账号或切校后丢弃旧请求响应，不把旧学校事实自动带入新上下文。

## 3. 搜索发现与资料流程

数据流为：可信会话 → 当前学校与偏好 → 已有公告检索/按需刷新 → 搜索候选 → 来源核验与正文读取 → 授权和 AI 许可检查 → 排序与资料包 → 对话回复与引用校验。

搜索引擎通过独立适配接口接入，首版实现选择 Tavily Search，凭据通过服务端 `TAVILY_API_KEY` 提供；真实供应商调用与账单未验证，不承诺免费。关闭或未配置时继续使用已有来源，明确显示“联网搜索未配置”；调用失败时显示“本次联网搜索未完成”，不清空已有公告，也不制造“没有相关公告”的结论。

首版只搜索所选学校相关公开公告。后端用学校官方名称、已核验官方域名与问题构造查询，不把完整兴趣档案、点击流水、邮箱或私人资料发送搜索服务。搜索摘要只能提供候选线索。正文读取继续执行公开 URL、DNS、重定向、时限、大小及访问限制检查；不读取本机/内网地址，不携带校园账号 Cookie，不绕过登录、VPN、验证码或 TLS 校验。

核验域名须来自维护者确认的学校官网或官方导航，不由模型凭域名猜测学校；未知域名和搜索转述不纳入事实依据。跟随重定向后再次核验，去重以规范原文链接和稳定标识为依据，不仅比较标题。已知公告沿用原 ID，新候选使用服务端产生的稳定候选 ID。未经核验的新页面不自动进入共享公告库或长期采集来源。

资料区分 `body`（正文已取得）、`title_only`、`snippet_only`、`unavailable` 四种读取状态。学校或来源未核验的候选只能展示待核验状态，不进入模型事实资料包。正文不可读时保留原文入口；附件默认未读，不承诺 OCR 或附件分析。

`allowAi` 和现有来源策略在打包、每轮续问及接受结果前都重新检查。私人邮件、私人资料不进入自动推荐/搜索，也不传给推送模块；用户明确选择且来源允许时才可用于本人对话。

## 4. 分工与最小接口

### 4.1 所有权

| 负责人 | 职责 | 交接要求 |
| --- | --- | --- |
| AI_module | 偏好管理、行为信号、推荐、搜索发现、对话、引用与额度适配 | 读取统一选校记录，产出可独立消费的推荐数据 |
| 首次接入负责人 | 学校必填引导、可选兴趣、老用户兼容、后续切校入口 | 学校保存成功后才能进入本校 AI 功能 |
| 推送负责人 | 离线调度、渠道、发送、去重、通知偏好、送达状态 | 使用服务端可信身份调用推荐能力，发送前重新核验权限与学校 |

AI_module 不创建推送定时器、不申请通知权限、不发送邮件，也不以推荐生成成功冒充通知送达。队友提交的学校与兴趣通过统一资料接口保存，避免各分支维护两份档案。

### 4.2 接口约定与落地映射

下表是能力契约。实际操作已在 `packages/contracts/src/assistant.ts` 定义并加入网关白名单：`ai.profile.get/save/clearBehavior`、`ai.behavior`、`ai.dismiss`、`ai.recommend`、`ai.chat.create/latest/get/send/step/cancel/resolve/clear`。部署前远端不可用。浏览器不得指定 owner 或可信身份；服务端取登录身份，校验 schoolId 与当前选择一致。

| 能力 | 输入 | 输出与约束 |
| --- | --- | --- |
| 读取背景 | 可信会话；后台调用使用经过认证的内部用户上下文 | schoolId、学校名、关注标签/关键词、自由描述目标、行为学习开关、偏好版本；未选校返回需引导状态 |
| 保存偏好 | 关注内容、行为学习开关、预期偏好版本 | 保存后的偏好与新版本；提供修改、清除兴趣、清除行为记录能力；并发冲突要求重新读取，不覆盖新版本 |
| 记录行为 | schoolId、itemId、事件类型 `open`、幂等事件 ID | 接受或忽略状态；先验证访问权；关闭学习不记录；收藏继续由现有收藏接口维护 |
| 检索与推荐 | schoolId、可选问题、是否请求联网、最多八篇的可选公告 ID | 最多五项推荐、搜索配置/执行状态、来源覆盖和缺失说明；资料使用范围与展示候选分开 |
| 创建/读取对话 | schoolId、可选 conversationId | 本人当前学校未过期的会话与消息；到期或无权限时拒绝读取 |
| 提交对话轮次 | conversationId、question、可选公告 ID、requestId | 轮次 ID、处理状态、完成回复、引用清单、官方剩余额度和到期时间；轮次可查询/取消，取消不是撤销已经发出的模型请求 |
| 推送交接 | 经过认证的内部用户上下文、schoolId、偏好版本、候选数量 | 生成时间、偏好版本、候选公告；不返回私人对话或行为流水，不调用模型生成推送文案 |

每项推荐至少包含：稳定公告/候选标识、schoolId、标题、来源名称、真实原文链接或 null、发布时间或 null、最近读取时间、推荐理由及依据类型、读取状态、来源核验状态、是否允许 AI。没有链接不能制造 URL。

模型引用清单另外绑定本轮 `R1` 等引用号、公告标识、学校、正文版本及原文 URL。多轮引用使用“轮次 ID + R 编号”识别，不能将上一轮的 R1 误认作本轮 R1。历史消息显示原引用，但失效正文不继续发送模型。

推送数据中的稳定标识用于队友去重，偏好版本与生成时间用于判断快照是否过时。推送端须在发送时重新检查学校、来源状态、可见性与通知许可，不能盲目发送旧快照。搜索不可用时也可交接已有来源推荐，并带上失败/覆盖说明。

## 5. 额度、保留与运行时指令

### 5.1 三轮官方回复

计划将官方按阅读任务计次改为每天最多三轮成功且通过校验、可读取的模型回复，北京时间零点重置；允许配置更低上限。内部检索、资料分批和汇总共计一轮，但各次模型调用仍受平台调用与 token 预算限制，不因“一轮”而无限调用。

发送前事务预占一个轮次；完成并通过来源校验后结算为已用。可确定的失败释放预占；网络超时或服务商处理状态不明时保留预占并暂停，不盲目重发或自动赠送次数。恢复时先查询原轮次。相同 requestId 返回原轮次，参数改变返回冲突。跨日继续处理仍结算到预占时所属日期，不能挪到次日重复扣次。

打开列表、查看详情、刷新、搜索和编辑偏好不调用模型、不扣官方次数，但依然消耗站点或搜索服务资源并需要限流。额度耗尽时仍可浏览和搜索；“超额提示”由程序显示，不再调用模型。真正调用模型做出的澄清回复也计一轮；明确缺少选校、空输入、额度不足等程序可判断的问题直接处理，不调用模型。

旧任务及其预占继续按旧规则结算，不因上线重置已用额度；新旧流程共用同一官方日账户，不能各赠三次。BYOK 继续作为可选高级入口，不扣官方次数，但受服务商计费和平台限制，Key 仅保留于当前页面内存，退出/刷新后清除，不进入档案、日志或对话。

### 5.2 数据保留

- 对话、消息、所用正文副本和中间笔记统一按会话创建满 24 小时拒读；追问不延长到期。到期不能再续问，用户另开新对话。
- 复用访问清理与每日定时兜底，后续把新增会话数据纳入清理；无人访问时不承诺准点物理删除。额度/幂等记账元数据与正文分开，清正文不重置额度。
- 明确兴趣及目标保存至用户修改或清除；学校使用已有选校记录。行为学习默认关闭，开启后仅保留近 30 天信号，查询时排除过期信号并由清理任务兜底删除；关闭时停止记录与使用并清除已有行为及派生权重。
- 账号隔离不依赖客户端缓存键。清除对话使结果立即不可读取；不删除用户自行下载的文件，不把私人上下文写入共享公告缓存。

### 5.3 指令同步

[对话式阅读规范](ai-reading-guide.md) 是对话 v2 最终回答规范，已通过 `tools/sync-ai-guide.mjs` 同步为运行时文本，`npm run typecheck` 检查与 MD 一致。对话任务指纹包含 v2 指南版本；`ai-service.ts` 在对话模式移除七节约束，高级报告仍保留 v1。中间笔记继续保持简短且带证据，不直接套用聊天回答格式。

后端继续执行授权、来源核验、日期证据检查和引用校验；提示词不能代替这些程序。现有引用校验能拦截未知编号与 URL，但不等于已经证明每句事实都受原文支持。无正文的资料不足场景应允许明确的无结论回复，不能为了通过“必须有引用”而编造 R 编号。

## 7. 场景示例与最终验收

以下全部为合成验收资料，不代表实际学校公告。学校为“示例大学”，A《校园编程赛报名通知》原文写“面向在校本科生，提交报名表，2026 年 10 月 25 日 17:00 截止”，B《图书馆讲座》只有标题。使用 `.invalid` 保留域名表达不可访问的测试链接，不作为真实推荐来源。

| 场景与输入 | 预期结果 |
| --- | --- |
| 首次无偏好：已选校，未填写兴趣，学习关闭，打开 AI 页 | 展示近期公告与“按发布时间展示”；不创建画像、不调用模型、不扣次数 |
| 主动推荐：用户填“编程、竞赛”，打开页面 | A 优先展示；理由为命中主动填写的关键词；列表由程序生成，不能声称已符合参赛资格 |
| 第一轮问“A 要准备什么” | “公告要求提交报名表，面向在校本科生。[R1](https://notice.example.invalid/a) 建议先核对你的学籍身份。”仅使用测试提供的正文；成功后剩两轮 |
| 第二轮追问“什么时候截止” | 沿用 A 的上下文，重新授权后回答“报名截止为 2026 年 10 月 25 日 17:00。[R1](https://notice.example.invalid/a)”；本轮重新绑定 R1；剩一轮 |
| 联网发现：用户要求“再找找本校新公告” | 后端搜索并读取已核验官方正文后才引用；显示本次搜索状态；候选不自动变成来源订阅；模型回复成功后计一轮 |
| 资料不足：问“B 要交多少钱”但只有标题 | 回复“目前只有标题，无法确认费用，需要正文”；不把未写费用解释为免费；引用仅证明标题来自候选 |
| 来源不可访问：页面要求校园登录 | 提示正文未读取、保留已核验原文入口；不编造内容，不绕过登录，不清空其他可用公告 |
| 搜索故障或未配置 | 展示失败/未配置状态，继续已有来源；不得回复“已搜遍网络”或“全校没有相关公告” |
| 已成功三轮后再次发送 | 程序显示额度耗尽，不再发送模型；浏览和搜索继续可用，不能把这条提示计作第四轮 |
| 请求超时后重试同一 requestId | 查询并返回原轮次；状态不明时保持暂停和预占，不重复调用或扣次 |
| 切学校、退出或换账号时旧请求才返回 | 丢弃旧响应；服务端阻止跨账号/学校读取，旧消息不进入新会话 |
| 来源撤回 AI 许可、删除公告或私人资料未授权 | 不发送对应正文，不接受基于失效资料的新结果；自动推荐和推送都不包含私人资料 |
| 清除行为或关闭学习 | 派生兴趣立即停止影响推荐；重复点击与过期信号不再起作用；主动兴趣仍可独立修改 |
| 会话满 24 小时或行为满 30 天 | 立即在读取/排序中排除，定时任务兜底清理；不声称已在精确时刻物理删除 |
| 推送模块独立调用 | 无需打开聊天页即可取得推荐快照；不含聊天正文和行为流水，发送端自己去重并核验许可 |
