## 界面行为

- 登录密码隐藏时显示闭眼图标，点击后变为睁眼并显示密码；再次点击隐藏，保留键盘操作、`aria-pressed` 与按钮焦点反馈。
- 公告使用实际 `item.title` 并完整换行。原“用 AI 生成摘要”改为“加入ai搭子”，可累计8篇，重复项不会再次加入，不切页、不创建对话、不调用模型。可通过提示或 AI 阅读入口查看资料；移除后可重新加入。右侧“用于 AI 阅读”勾选框删除。
- 点击侧栏底部“个人工作区”打开弹窗，顶部显示当前账号用户名（现有邮箱身份），下设“账号安全”“我的学校”“服务模型”。手机侧栏收起时仍可点击头像进入。
- 学校选择、名称搜索、目录分页、申请入口、采集覆盖范围从公告页整体移动到“我的学校”。复用原 `school.select` 与账号保存逻辑，换校仍清空旧资料选择并读取对应学校；公告页保留分类、时间和关键词筛选。

## 密码邮件重置

用户明确选择向当前邮箱发送重置邮件。按钮调用本站 `POST /.netlify/functions/auth?op=password-recovery`，请求体为空对象；服务端检查同源、官方 SDK 的当前会话、合法邮箱和初始站点配置，拒绝任何客户端收件人字段。调用锁定版本 `@netlify/identity` 的 `requestPasswordRecovery()`，不会使用提醒邮件的 DirectMail 凭据。前端阻止并发请求，成功后60秒内禁用重发；服务端保留平台本身的发送限制。

邮件返回网站时，`recovery_token` 立即从 URL 取入内存并移除，不展示、不存 Storage。进入新密码和确认密码表单，要求12至256位且一致；提交立即清空两框，使用官方 `recoverPassword()` 完成令牌兑换及更新。成功后从本站认证端点重新核验会话，且会话 UID 必须与恢复令牌对应的 SDK 用户一致，再读取本人工作区。失败或旧 Cookie 指向另一账号时，清理 SDK 可能建立的部分会话，只显示固定本站错误；不自动重试、不展示上游响应。已打开页面收到恢复链接也会先清空旧工作区。原邮箱确认、注册与邀请流程保留。

无需新增变量或数据库迁移。正式使用需部署代码并保证该站点 Netlify Identity 的密码恢复邮件及回跳地址正常。现有 Identity 邮件说明见 [官方文档](https://docs.netlify.com/manage/security/secure-access-to-sites/identity/identity-generated-emails/)；实现接口和行为也核对了项目锁定 SDK 的源码与 README。

部署后用真实邮箱验证：从个人工作区发送邮件、打开本站恢复链接、设置新密码、退出后用新密码登录；失效链接应显示可理解的错误。此轮仅测试合成发送器与 SDK，不代表真实邮箱送达。

## API 和模型

弹窗复用现有 `AiProviderSettings`，仍按账号加密保存密钥，支持原四种协议、多模型、编辑/删除。保存与启用独立：保存后需点击“使用此配置”；“使用官方 AI”明确清除个人服务商选择。密钥不回显，编辑或弹窗关闭时清空草稿。

AI 阅读页原服务设置入口保留。弹窗写入的可信服务端状态同步到已打开的 AI 页，使旧配置草稿和迟到读取失效，保留现有对话、问题和额度，不重新装载整个会话或自动调用模型。已提交请求可能仍在执行；配置变化停止自动继续批次，后续仍以服务器固定的资料许可、任务状态和服务商版本校验为准。删除当前配置后，不自动改用其他服务。
