# AI 阅读个人服务商：使用与接入

实现日期：2026-10-25（北京时间）。本功能位于 `codex/ai-companion-model-settings`，基于 main `b6e383f`；代码已完成本地验证，功能分支用于审核；GitHub 分支上传不等于正式网站上线。

## 页面操作

1. 进入 AI 阅读，展开提问框下面的“服务模型调整”。
2. 在“我的服务商”点击“添加服务商”，选 DeepSeek、OpenAI、Anthropic、Gemini 预设或自定义。
3. 填写配置名称、协议、HTTPS 基础地址、自己账号可用的模型 ID 和 API Key。基础地址保留 `/v1`、`/v1beta` 等版本路径；不带查询参数。每行一个模型，选择默认模型。
4. 点击“保存配置”。这一步不调用模型，也不自动启用。
5. 在对应配置中选择模型，点击“使用此配置”，再发送新问题。刷新后恢复账号已保存的选择；选择“官方 AI”会清除个人当前项。

每个账号最多10套配置，每套最多20个模型。数据不与其他账号共享。API Key 保存后清空输入框，编辑时留空保留旧 Key；变更地址或协议必须重新填写。删除需要二次点击，当前选择随之清空。

每轮固定发起时的配置和版本。切换当前项不改变旧轮次；编辑或删除配置会停止使用旧版本的未完成轮次。在途请求可能已经由服务商处理，本站不能撤回，会丢弃失效结果。状态不明时不会自动重发，需在服务商控制台核查用量后手动结束本轮。个人 API 不扣官方日次数，也不会失败后自动改用官方 AI。

保留“临时 API（仅本页）”：DeepSeek/OpenAI Key 只存在页面内存，刷新或退出需要重填。个人配置和临时 API 都不会把 Key 写入浏览器 localStorage/sessionStorage。

## 站点接入

上线前需要两部分，代码本身没有执行生产操作：

1. 正常部署应用追加迁移 `20261024000300_ai_provider_profiles.sql`。默认与旧 `AI_module` 兼容目录均追加同内容，旧迁移不改写。不要在函数请求中建表。
2. Netlify 为需要启用功能的部署上下文新增服务端环境变量 `AI_PROVIDER_ENCRYPTION_KEY`。值为随机32字节的标准 Base64 编码；设置为秘密值，不能加 `VITE_` 前缀。若套餐不能单选 Functions，使用套餐已有作用域即可。部署后函数从 `Netlify.env.get` 读取。

主密钥应在管理员自己的可信本机生成，保存在密码管理器和 Netlify，不能提交到 Git、截图或发送给其他用户。可在自己终端运行下面的命令生成，生成值不放入文档或聊天：

```sh
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64'))"
```

同一数据库的函数必须使用同一主密钥；需要隔离测试时使用独立预览数据库和主密钥。主密钥丢失或直接替换后，已有 Key 无法解密，需要用户重新输入。初版没有在线密钥轮换工具。缺少或格式无效时，页面显示“个人配置保存待启用”，官方和临时 API 仍可用；不会降级保存明文。

SQL 只保存 AES-256-GCM 密文与认证信息，主密钥与数据库分开；接口只返回配置元数据。解密仅发生在服务端，执行请求携带原配置引用。网络只支持公网 IPv4 HTTPS:443；IPv6-only、私网、重定向接口和需要自定义认证头的接口不在首版支持范围。

## 本地验证

已完成锁定依赖安装、类型与指南同步检查、前端117项测试、后端260项测试、普通构建和 Netlify 完整8函数产物构建。新增测试覆盖真实本地 SQL 的密文与账号隔离、并发保存、旧版本任务、配置在模型请求中变化、状态不明恢复、四协议请求和 DNS/重定向限制。

本地合成网页预览包含添加、保存、启用、编辑、删除和模拟回答；检查桌面1366×1100及手机390×844，无横向溢出，Storage 为空。合成 transport 只验证前端行为，服务端存储另由真实本地 SQL 测试验证。没有调用真实模型、生产登录、远端数据库或收费服务；真实模型效果与兼容端点需上线后用本人账号单独验收。
